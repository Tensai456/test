## B. THINKBOOK (ตัดสินใจอะไร · ทำไม · ทางที่ไม่เอา)

**B.1 โฟลเดอร์ใน repo เดิม แทน repo ใหม่**
- เหตุ: jing ตั้งเงื่อนไข "ถ้าดึงเฉพาะได้ ไม่ต้องแยก" → sparse-checkout ทำได้ · bot-hub ต้องใช้ mc-lab คู่กันอยู่แล้ว
- ไม่เอา: repo ใหม่ (ต้องผูก mc-lab ด้วย submodule/package = ซับซ้อนเกินตอนนี้) · แยกทีหลังพร้อมประวัติได้

**B.2 เว็บ Node ล้วน (node:http) แทน WPF / express**
- เหตุ: jing ใช้ Win + Mac + Linux + มือถือ → เว็บเปิดได้ทุกเครื่อง · node:http พอสำหรับ ~10 route ไม่ต้องเพิ่ม dependency
- ไม่เอา: WPF (Windows อย่างเดียว) · express/React (เกินจำเป็นสำหรับหน้าเดียว)

**B.3 บอต 1 ตัว = 1 process (fork)**
- เหตุ: บอตตัวหนึ่งพัง/ค้าง/โดนเตะ ไม่ลากตัวอื่น · ปิดตัวเดียว = kill process
- แลกกับ: RAM ต่อตัวสูงกว่ารันรวม [ไม่แน่ใจ ตัวเลขจริง — วัดบนเครื่อง jing ตอนรัน 8 ตัว]

**B.4 กติกาผสมสมอง**
- มี `rules` ในชุด → reflex ด่วน (prio ≥50) + veto ชนะเสมอ = ตาข่ายความปลอดภัย
- ชิ้นอื่นถามตามลำดับ ชิ้นแรกที่ไม่คืน null ชนะ → เขียน `fly-small+old` = ถามแมลงวันก่อน ไม่ตอบค่อยถามสมองเดิม
- สมองล้วน (`fly-small`, `old`) **ไม่มีตาข่าย** — ตั้งใจ เพื่อวัดเทียบได้ว่าสมองนั้นเก่งจริงแค่ไหน
- สมองที่ยังไม่เสียบ → ข้าม + ขึ้นป้าย "สมองยังไม่เสียบ" (ไม่ crash)
- สมองภายนอกต้องตอบทันที (ถูกเรียก 5 ครั้ง/วิ) → Ollama ต้องยิง async แยกแล้วเก็บคำตอบล่าสุด

**B.5 แก้ mc-lab จุดเดียว: `brainPlugin({ decide })`**
- เหตุ: ให้ hub ส่งสมองที่ผสมแล้วเข้า plugin เดิม → ได้ executor/veto/แก้บั๊กเกิดใหม่/knockback ของเดิมครบ ไม่ต้องก๊อปโค้ด
- ไม่ระบุ = ใช้ decide เดิม (เข้ากันได้ย้อนหลัง · เทส 76/76 ผ่าน)

**B.6 บันได = ต่อ chain ของ mc-lab** (`first_night → iron_kit → nether → end → dragon` = 31 ขั้น)
- เหตุ: ใช้นิยาม "เสร็จ" ชุดเดียวกับสมอง → ตัวเลขไม่ขัดกับที่สมองคิด
- จำ "สูงสุดที่เคยถึง" แยก เพราะของถูกใช้ไปแล้ว ขั้นเก่าจะดูเหมือนยังไม่เสร็จ (เช่น กินอาหารหมด)
- ค้าง = อยู่ขั้นเดิม ≥15 นาทีเวลาเกม [คิดเอง — ปรับตามข้อมูลศุกร์]
- ข้อจำกัด: ขั้นที่วัดด้วย flag (เช่น "เข้านรกแล้ว") ต้องมีคนตั้ง flag — ตอนนี้ยังไม่มี → อาจค้างผิด ๆ ที่ขั้นนั้น

**B.7 จับชื่อเรียก (wake)**
- ทำรูปกลางก่อนเทียบ: ตัดวรรณยุกต์ · ตัดตัวการันต์ทั้งตัว (ร์) · รวมสระ/พยัญชนะเสียงใกล้ (า/อ, ิ/ี, ล/ร, ส/ซ/ศ/ษ …) แล้ววัด Levenshtein แบบหน้าต่างเลื่อน
- เกณฑ์ ≤0.34 (ผิดได้ ~1 ตัวต่อ 3 ตัว) — ตั้งจากเทส [ต้องปรับด้วยเสียงจริง]
- ออนไลน์ตัวเดียว → ชื่อตัวไหนก็ได้/คำเรียก ("บอท") ไปหาตัวนั้น (ตามที่ jing ขอ)
- เพิ่มชั้นที่สอง: ส่งรายชื่อบอตเป็น `--prompt` ให้ Whisper → STT สะกดชื่อถูกตั้งแต่ต้น
- ไม่เอา: phonetic algorithm สำเร็จรูป (ไม่มีตัวที่ดีสำหรับไทย) · LLM ตีความ (ช้า + เปลือง)

**B.8 แยก `login` กับ `display`**
- เหตุ: เซิร์ฟ offline-mode ผูกผู้เล่นกับชื่อ → เปลี่ยน login = คนใหม่ ของ/บ้านหาย · "เปลี่ยนชื่อ" ที่ jing ต้องการน่าจะหมายถึงชื่อเรียก → แก้ `display` ได้อิสระ · ชื่อในเกมใช้ `/nick` (EssentialsX) ถ้าต้องการ

**B.9 ยังไม่ทำ executor ตามแผน (ตั้งใจ)**
- เหตุ: เป็นงานใหญ่ (ตัดไม้/ขุด/คราฟต์/เผา ทีละขั้น) และต้องรู้ก่อนว่าโค้ดเดิมของรุ่นพี่ทำอะไรได้แล้ว · ถ้าโค้ดเดิมทำงานได้ → hub แค่ดู+log คุ้มกว่าเขียนใหม่
- **ต้องให้ jing ตัดสิน** (HANDOFF §4 ข้อ 1)

**B.10 รุ่นน้องแย้งแบบหยาบ**
- รุ่นน้องเห็นรุ่นพี่ผ่านโปรโตคอลเท่านั้น (ไม่เห็น inv/food — mc-lab IMITATION_DESIGN §1.3) → สร้างมุมมอง "รอบตัวรุ่นพี่" (ม็อบวัดระยะจากรุ่นพี่, hp/food = 20) ป้อนสมองของรุ่นน้อง
- แย้งเมื่อเห็นอันตราย (reflex ≥50) ค้าง ≥2 วิ · ผลตัดสินยัง unknown เสมอ

**B.11 log ใช้สคีมาเดียวกับ replay**
- เหตุ: วันศุกร์ใช้ `mc-lab/tools/replay` ได้ทันที ไม่ต้องแปลง · ชื่อไฟล์ `senior_*.jsonl` / `intern_*.jsonl` ตามที่ replay หา

**B.12 ความปลอดภัย**
- ผูก 127.0.0.1 เป็นค่าเริ่ม · เปิด LAN ต้องตั้ง `HUB_TOKEN` (โปรแกรมไม่ยอมเริ่มถ้าไม่ตั้ง) · token/รหัสอยู่ `.env` เท่านั้น (กฎ jing ข้อ 8)

**B.13 โหมดจำลอง (`HUB_SIM=1`)**
- เหตุ: เครื่องคลาวด์ไม่มีเซิร์ฟ → ต้องมีทางเทสหน้าเว็บ/ท่อ log/การสลับสมองโดยไม่ต่อเซิร์ฟ · ใช้สมองจริงกับ state ปลอม · ได้ของตามขั้นแผนให้ % บันไดขยับ
- ⚠ ตัวเลขจากโหมดจำลองไม่มีความหมายกับบอตจริง
