# PVP_TEST_MATRIX — ตารางเทส PvP (ชุดอาวุธ × เกราะ × ฝั่ง)

> **sim-only:** `scripts/run_duel_matrix.mjs` และ `lib/pvp/duel_sim.mjs` เป็นตัวจำลอง 1 มิติ ไม่เชื่อมเซิร์ฟ/บอตจริง → ผ่านที่นี่ = "ผ่านระดับจำลอง" เท่านั้น (SR §4). การผ่านจริงต้องรันบน Paper 26.2 กับบอตจริง (ยังไม่ได้ทำในเอกสารนี้)
> ตัวย่อ: **PB** = docs/PVP_PLAYBOOK.md · **SR** = docs/SIM_RESULTS.md

## 1. เกณฑ์ผ่าน
| ข้อ | เกณฑ์ | ที่มา |
|---|---|---|
| ชนะ | **≥ 90% ต่อชุดอาวุธ (kit)** | brief §1 |
| จำนวนรอบ | **n ≥ 10 ต่อเซลล์ และสลับฝั่ง (A/B) เท่า ๆ กัน** | brief §1 |
| ห้ามชนะผิดกฎ | ทิ้ง/เลิกใช้อาวุธ หรือขังตัว = นับแพ้ทันที | kb/team/pvp-bots.md |
| เสมอ/หมดเวลา | นับ "ไม่ชนะ" (ไม่เอาไปบวกฝั่งใด) | [คิดเอง] |
**ข้อควรระวังสถิติ [คิดเอง]:** n=10 ผ่าน ≥90% = ชนะ ≥9/10 ซึ่งช่วงความเชื่อมั่นกว้างมาก (Wilson 95% ของ 9/10 ≈ 0.60–0.98 — คำนวณเอง) → ถือเป็น "ผ่านขั้นต้น" แล้วเพิ่ม n=30+ ก่อนประกาศผ่านจริง.

## 2. ตารางเทส (ชุด × เกราะ)
เกราะอ้างอิงตาม lib/pvp/weapons.mjs: none / leather / iron (armor 15) / diamond (20, toughness 8) / netherite (20, toughness 12, kbRes 0.4). ค่า leather ในโค้ดเป็น [ไม่แน่ใจ].

| ชุด (kit) | none | leather | iron | diamond | netherite | สถานะล่าสุด (บอตใหม่ vs OldSpar n=12) |
|---|---|---|---|---|---|---|
| ดาบเหล็ก | ☐ | ☐ | ☐ (SR ทำแล้ว) | ☐ | ☐ | 100% |
| ดาบเพชร | ☐ | ☐ | ☐ | ☐ | ☐ | 64% (ต่ำกว่าเหล็ก ผิดคาด) |
| ขวาน | ☐ | ☐ | ☐ | ☐ | ☐ | ~80–83% |
| ดาบ+ธนู | ☐ | ☐ | ☐ | ☐ | ☐ | ~80–83% |
| ครบชุด | ☐ | ☐ | ☐ | ☐ | ☐ | ~80–83% |
| ดาบ+กระบอง+ลูกลม (สูง 4 / 8) | ☐ | ☐ | ☐ | ☐ | ☐ | กระบองเดี่ยว 8–25% |
| ธนู | ☐ | ☐ | ☐ | ☐ | ☐ | 67% |
| หน้าไม้ | ☐ | ☐ | ☐ | ☐ | ☐ | ~50% (จำลองยังไม่รองรับ) |
| ตรีศูล | ☐ | ☐ | ☐ | ☐ | ☐ | ~50% (จำลองยังไม่รองรับ) |
| หอก (jab / charge) | ☐ | ☐ | ☐ | ☐ | ☐ | 0% |
แต่ละเซลล์ ☐ = ต้องรัน n≥10 สลับฝั่ง · ตัวจำลองรองรับ: ดาบ, ขวาน, กระบอง, หอก (jab), ธนู, โล่, คริ, w-tap, ping — **ไม่รองรับ** หอก charge, หน้าไม้, ตรีศูล, ยา, แอปเปิลทอง, ไข่มุก, เบ็ด, sweep หลายตัว (SR §4).

## 3. กันลำเอียงฝั่ง (side bias)
| วิธี | รายละเอียด |
|---|---|
| สลับฝั่งในโค้ด | `matchup()` ใน duel_sim.mjs สลับ A/B ทุกรอบ (`flip`) และเพิ่ม seed ต่อรอบ — ตัวจำลองทำให้แล้ว (อ่านจากโค้ด `matchup(pa,pb,{n,seed})`) |
| เซิร์ฟจริง | สลับตำแหน่งเกิด/ทิศหัน/ขอบสนามทุกรอบ (รอบคู่ = A ซ้าย, รอบคี่ = A ขวา) ใช้พื้นราบเท่ากัน [คิดเอง] |
| ping | ตัวจำลองล็อก ping 10–50 ms ต่อฝั่ง; ping 10 vs 50 แทบไม่ต่าง (45% vs 46%) แต่ 10 vs 150 ต่าง (60% vs 40%) → **คุม ping เท่ากันทั้งสองฝั่ง** (SR §2) |
| ตรวจ | รายงาน win% แยกฝั่ง A-ซ้าย / A-ขวา ถ้าต่างกัน >15 จุด % ถือว่าลำเอียง [เกณฑ์ตั้งเอง] |
| เกราะ/HP/อาหารเท่ากัน | เริ่ม hp 20, เกราะตามช่อง, อาหารเต็ม, ไม่มีเอฟเฟกต์ |
| ห้ามใช้ผลที่ผิดตัวจำลอง | w-tap แพ้ (SR: ข้อจำกัด 1 มิติ) และ "99% กระบองสูง 8" (เกินจริง) ห้ามใช้เป็นเกณฑ์ผ่าน |

## 4. วิธีรันตัวจำลอง
```
node scripts/run_duel_matrix.mjs 400     # n ต่อแถว (ค่าเริ่ม 400) → พิมพ์ตาราง markdown
node --test test/pvp.test.mjs            # เทสฟังก์ชันล้วน (SIM_RESULTS ระบุ 23/23 ผ่านทั้งชุด test/*.test.mjs)
```
- สคริปต์ **มี 14 แถวตายตัว** (ดาบ vs สแปม, w-tap, คริ, โล่, ขวาน vs ดาบ+โล่, เพชร vs เหล็ก, กระบอง 3 แบบ, หอก jab, ดาบ+ธนู, ping 2 แบบ) และใช้เกราะ `iron` ทั้งคู่ (ค่าเริ่ม `armor: 'iron'` ใน duel_sim) → **ไม่มีตัวเลือกเกราะ/ชุด ผ่าน CLI**: ต้องแก้ `rows` ในสคริปต์ (หรือสร้างสคริปต์ใหม่) โดยใส่ `armor: 'diamond'` ฯลฯ ใน profile เช่น `{ weapon:'iron_sword', armor:'diamond' }` — duel_sim รองรับ field `armor` (ARMOR ใน weapons.mjs)
- ผลลัพธ์: คอลัมน์ A ชนะ / B ชนะ / เสมอ-หมดเวลา / เวลาเฉลี่ย / A คริ-ฮิต / A smash
- ที่มา kb/sim/pvp-results.md ถูกสร้างจาก SIM_RESULTS ด้วย split_kb.mjs — ห้ามแก้มือ และไม่ต้องรัน split_kb ในงานนี้
- ผลเก่า (n=400) อยู่ใน SR §2 ใช้เทียบ regression

## 5. ขั้นตอนเทสบนเซิร์ฟจริง (ยังไม่ได้ทำ — แผน)
1. เตรียมสนามราบ ปลอดภัย ไม่มีลาวา/ขอบ (ไม่เกี่ยวกับ "ห้ามขังตัว": เป็นสนาม ไม่ใช่กำแพงของบอต)
2. ให้ทั้งสองฝั่งได้ชุดเดียวกันจาก `/give` หรือ creative [คิดเอง]
3. รัน n≥10 สลับฝั่งต่อเซลล์ที่ผ่านตัวจำลองแล้ว; บันทึก: ผู้ชนะ, เวลา (tick), HP เหลือ, ฮิต/คริ, smash, เหตุที่จบ (ตาย/หมดเวลา/ผิดกฎ)
4. ตัดสินผลภายใน 120 วิต่อรอบ (ตั้งเอง; ตัวจำลอง maxTicks 2400 = 120 วิ)
5. รวมผลเทียบเกณฑ์ §1

## 6. การเทสทีม (เชื่อมกับ PVP_TEAM_TACTICS)
| เคส | วัด | ผ่าน |
|---|---|---|
| 2v1 | ชนะ, ตายฝ่ายเรา, ฮิตซ้ำใน i-frames | ≥90% ชนะ และตายฝ่ายเรา = 0 (n≥10) [ตั้งเอง] |
| 2v2 | เหมือนกัน | ≥90% |
ตัวจำลองเป็น 1v1 → ต้องเขียนตัวจำลองเพิ่มหรือเทสเซิร์ฟจริง.

## 7. สรุป 3 บรรทัด
- **ทำอะไร:** ตารางเทส 10 ชุด × 5 เกราะ พร้อมเกณฑ์ผ่าน ≥90%, n≥10 สลับฝั่ง, วิธีกันลำเอียง และวิธีรัน run_duel_matrix.mjs (sim-only)
- **ตัวเลขสำคัญ:** ผ่าน ≥90% · n≥10 · สคริปต์มี 14 แถว เกราะเหล็กทั้งคู่ · ping 10 vs 150 = 60/40 → คุม ping · n=10 ที่ 9/10 มีช่วงเชื่อมั่นกว้าง (~0.60–0.98 คำนวณเอง)
- **ยังไม่ได้ verify:** ไม่ได้รันสคริปต์ในงานนี้ (ใช้ผลเก่าใน SR) · ไม่ได้ยืนยันบนเซิร์ฟจริง · ตัวจำลองไม่รองรับหอก charge/หน้าไม้/ตรีศูล/ทีม · ไม่ได้เปิดอ่านเต็มของ duel_sim.mjs (ยืนยันเฉพาะ flip/armor จากการ grep)
