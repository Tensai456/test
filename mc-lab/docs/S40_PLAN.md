# S40_PLAN — ให้ผู้ฝึกงานลงเล่นจริง · พร้อมไปโลกถัดไป · ลองแยกทีมไกล ๆ

> สถานะ: แผนบนกระดาษ จากการอ่านโค้ด/เอกสารแล็บ (`lib/chain.mjs`, adapter, FUZZ_LOG, EVENT_INVENTORY, MINEFLAYER_INTEGRATION) · **ยังไม่ได้ทดสอบกับเซิร์ฟ/บอตจริง** (ยืนยันได้ระดับจำลอง)
> **เกณฑ์ตัวเลขทุกตัวในเอกสารนี้ = [คิดเอง] เป็นค่าตั้งต้นที่ต้องปรับหลังเห็น baseline จริงของวันศุกร์** (IMITATION_DESIGN §7.3) ไม่มีตัวเลขไหนมาจากข้อมูลจริงของแล็บ ยกเว้นที่ระบุที่มาไว้ · "s40" = โลกถัดจาก world_s39 [ไม่แน่ใจ ว่า jing ตั้งชื่อโลกถัดไปว่า s40 — ใช้ตามชื่อไฟล์ที่สั่ง]
> ศัพท์ metric (agreement, agreement_good, objection accuracy, coverage, veto-breach rate ฯลฯ) นิยามไว้แล้วใน `docs/IMITATION_DESIGN.md` §7

## 0. หลักการ

1. **ปล่อยทีละขั้น ย้อนกลับได้เสมอ** — ผ่านประตู → ขยับขั้น · พลาด → ถอยขั้นเดียว ไม่ใช่ถอยทั้งหมด
2. **ตัวเลขเดียวไม่พอ** — ทุกประตูต้องผ่านทั้ง (ก) ความตรง (agreement) (ข) ความปลอดภัย (ตาย/veto) (ค) ความครอบคลุม (ประเมินได้กี่ % ของเวลา) · agreement สูงบนข้อมูลที่ประเมินได้แค่ส่วนน้อย = ไม่ผ่าน
3. **เกณฑ์สัมพัทธ์กับรุ่นพี่ที่ "วัดจริง" ใน s39** ไม่ใช่ตัวเลขลอย ๆ — รุ่นพี่ตายเฉลี่ย 4.2 ครั้ง/ชม. ในสถิติ 34 โลก (brief §1) เป็นเพดานที่ "ไม่ควรแย่กว่า" ไม่ใช่เป้า
4. **fuzz ผ่าน ≠ พร้อมเล่นจริง** (§2)

## 1. ระดับ (tier) ของผู้ฝึกงาน

| Tier | ชื่อ | ผู้ฝึกงานทำอะไร | ควบคุมตัวละคร? |
|---|---|---|---|
| T0 | ผู้ชม (ตอนนี้ s39) | เกาะดูรุ่นพี่ คิดเงา แย้ง บันทึก | ไม่ |
| T1 | ผู้ช่วยเบรก | เหมือน T0 + **อนุญาตให้ทำเฉพาะ reflex ปลอดภัย** (กิน, หนีครีปเปอร์, ว่ายขึ้นเมื่ออากาศหมด, หยุดเมื่อชังก์ไม่โหลด = `DEFAULT_EXECUTORS` ของ `mineflayer_brain.mjs`) ถ้าเห็นรุ่นพี่ใกล้ตายก็ไม่ช่วยตัวรุ่นพี่ — ช่วยแค่ตัวเอง | บางส่วน (8 ท่าค่าเริ่ม) |
| T2 | เล่นจริงมีผู้คุม | ลงเล่นเองใกล้รุ่นพี่/ฐาน ทำตาม `decide()` เต็มรูป + executor ครบ (ต้องเขียนเพิ่ม §2.2) คนดูตลอด พร้อมสั่งหยุด | เต็ม (รัศมีจำกัด) |
| T3 | เล่นจริงอิสระ | เหมือน T2 ไม่จำกัดรัศมี/ไม่ต้องมีคนจ้อง แต่มี kill switch | เต็ม |
| T4 | แยกทีมไกล | §5 | เต็ม |

## 2. ข้อเท็จจริงด้านความปลอดภัยที่มีอยู่ (และที่ยังขาด)

### 2.1 สิ่งที่มีหลักฐาน (จากไฟล์แล็บ)
- `decide()` = reflex + veto + plan · `REFLEX_MIN = 50` · veto บังคับเสมอ แต่ไม่แย่งลำดับกับ reflex ที่ต้องทำ (เช่น หนีลาวา)
- fuzz (จำลอง): ทุกเหตุการณ์ ≥2,000,000 ตัวอย่าง · `chain` สะสมหลายล้าน · `chainDeep` ≥8,000,000 ล่าสุด 0 ช่องโหว่ (FUZZ_LOG) · buildHome 2,000,000 ✅
- ประวัติชี้ว่า fuzz เคยเจอช่องโหว่จริงและปิดแล้ว (รอบ 1: 75,424; รอบ 2: 132; รอบ 521: 74,244 = ผลลวงจากรัน split_kb ระหว่าง fuzz) → **ห้ามรัน `scripts/split_kb.mjs` ระหว่าง fuzz/เล่นจริง** (บทเรียนจาก FUZZ_LOG)
- มี API ถามก่อนทำ: `bot.brain.allowed(action)` คืน `{ok, vetoes[]}` (action: sleep, attack, drop_weapon, wall_in, mine_ore, open_container, mine_gold, place_block, build_wither, drink_ominous, build_shelter, elytra_launch, pvp_engage, parkour, mlg_practice)
- มีช่วงพักหลังเกิดใหม่ (respawnGrace 60 tick ห้ามวางบล็อก + justDied) แก้บั๊ก "เกิดปุ๊บวางบล็อก"
- เหตุการณ์ error: `brain:error`, `brain:decision`, `brain:died`, `brain:respawned`

### 2.2 ช่องว่างระหว่าง "fuzz ผ่าน" กับ "เล่นจริงได้" (ต้องปิดก่อน T2)
| ช่องว่าง | หลักฐาน | ผลถ้าไม่ปิด |
|---|---|---|
| executor ค่าเริ่มมีแค่ 8 ท่า (drowning, creeper-fusing, charged-creeper, falling[แค่ถือของ], eat×3, chunk-unloaded) ส่วน 80+ กฎ **ส่ง event ให้โค้ดบอตเลือกท่า** | MINEFLAYER_INTEGRATION §3 | กฎตัดสินถูกแต่ไม่มีใครลงมือ → ผู้ฝึกงาน "รู้ว่าควรหนี" แต่ยืนอยู่ |
| ท่า falling: "การวาง/เทน้ำตอนใกล้พื้นยังเป็นหน้าที่โค้ดบอต" | integration §3 | ตกที่สูงตาย (คอขวดเก่า) |
| ยังไม่ได้รันกับเซิร์ฟจริง (บิตติดไฟ 0x01, ระยะตกที่คำนวณเอง) | integration §4 | ตัวชี้ผิด → กฎ on-fire/falling ผิดจังหวะ [ไม่แน่ใจขนาดความคลาด] |
| `team`/`flags` (inBase, nearVillage, raidActive, oreClaimed, invFull, thunder) ต้องมีโค้ดฝั่งบอตส่ง | integration §4 | กฎกลุ่มทีม/ฐาน/บอสทำงานไม่ครบ |
| fuzz ไม่วัดค่าหน่วง/แล็ก/ชังก์ไม่โหลด/ping จริง | FUZZ = สุ่ม state | ทดสอบจริงต้องดู |
| นับกฎ 102 ใน triggers.json (ตอนนับ 7 ต.ค.) vs "101" ใน FUZZ_LOG/brief | ไฟล์จริง | ถ้าเพิ่มกฎหลัง fuzz ล่าสุด กฎส่วนเกินยังไม่ถูก fuzz → ต้อง fuzz ใหม่ก่อน T2 |
| ปัญหา mineflayer 26.x (moved too quickly หลัง /tp, spectator โดนดัน, player_input, knockback 26.1) | brief งาน 11 (`MINEFLAYER_26X_ISSUES.md`) — ฉันไม่ได้อ่านผลงานนั้น | ผู้ฝึกงานที่เปลี่ยนจากโหมดผู้ชมมาเล่นจริงอาจเจอพฤติกรรมใหม่ที่ s39 ไม่เคยเจอ [ไม่แน่ใจ] |

**สรุป:** ก่อน T2 ต้องปิดอย่างน้อยแถว 1–4 (executor ครบ, MLG ลงมือจริง, ตรวจสอบกับเซิร์ฟ, ป้อน flags/team)

## 3. เกณฑ์ให้ผู้ฝึกงานลงเล่นจริง

> ตัวเลขทั้งหมด [คิดเอง]; "N" = จำนวนตัวอย่างขั้นต่ำก่อนเชื่อตัวเลข (ข้อมูล s39 บอกตอนศุกร์ว่ามีพอไหม)

### 3.1 ประตู G1: T0 → T1 (ผู้ช่วยเบรก)
ต้องผ่านครบ:
| # | เกณฑ์ | ค่าตั้งต้น | วัดจาก |
|---|---|---|---|
| a | **agreement_good** บนช่วงภัย (มี reflex ≥50 ยิง) ของผู้ฝึกงานที่ใช้กฎ (Sonar27/29/30 หรือที่มี `decide()` ตัวจริง) | ≥ 90% [คิดเอง] | replay (IMITATION_DESIGN §4) |
| b | **sanity check ความสอดคล้อง pipeline**: ผู้ฝึกงาน 27 (กฎล้วน) vs replay `decide()` ในช่วงเดียวกัน | ตรง ≥ 99% [คิดเอง] (ควรตรง 100% โดยโครงสร้าง; ที่ไม่ตรง = บั๊ก logger/แปลง) | replay §4.4 |
| c | `veto-breach` ของ**ผู้ฝึกงานเอง** (ถ้ามีท่าที่ไม่ได้ผ่านการ `allowed()`) | 0 | log |
| d | ครอบคลุมการประเมิน: สัดส่วนแถวที่ประเมินได้ | ≥ 70% [คิดเอง] และรายชื่อกฎที่ประเมินไม่ได้ต้องไม่รวมกฎเอาตัวรอด lv2–lv3 | replay `_missing` |
| e | ทดสอบ executor T1 ครบ 8 ท่าในเซิร์ฟทดสอบ/แท่นทดลอง | ผ่านทุกท่า | ทดสอบมือ (ไม่ใช่ fuzz) |

### 3.2 ประตู G2: T1 → T2 (เล่นจริงมีผู้คุม)
| # | เกณฑ์ | ค่าตั้งต้น | หมายเหตุ |
|---|---|---|---|
| a | **objection accuracy** (right ÷ (right+wrong)) | ≥ 75% [คิดเอง] และ **coverage** (ตัดสินได้) ≥ 60% [คิดเอง] | ถ้า unknown สูงกว่า 40% ตัวเลขนี้ไม่น่าเชื่อ ต้องเพิ่มความสามารถตัดสินก่อน |
| b | **false-alarm rate** (wrong ÷ แย้งทั้งหมดที่ตัดสินได้) | ≤ 25% [คิดเอง] | |
| c | **agreement_good** ภาพรวม | ไม่ต่ำกว่า baseline majority-class เกิน X จุด [คิดเอง — ตั้ง X หลังเห็น baseline ศุกร์] | อย่าตั้งตัวเลขตายตัวก่อนเห็นข้อมูล |
| d | **ช่องว่างการตาย** บน holdout (ตายโดยไม่มี reflex ยิง) | ลดลงเทียบก่อนปรับ และ = 0 สำหรับสาเหตุกลุ่ม lv2 (ตกที่สูง จมน้ำ ไฟ ลาวา ติดบล็อก) | ถ้ายังมี = ห้ามขึ้น T2 |
| e | ปิดช่องว่าง §2.2 แถว 1–4 + fuzz ซ้ำถ้ามีการแก้กฎ | เสร็จ | |
| f | ซ้อมเซิร์ฟทดสอบ (ไม่ใช่โลก s40) ด้วยผู้ฝึกงาน 1 ตัว ≥ [คิดเอง] 1–2 ชม. เล่นจริง | ตายไม่เกินรุ่นพี่ใน baseline (4.2/ชม.) และ **ไม่มีการตายจากสาเหตุที่มีกฎอยู่แล้ว** (ตก/ลาวา/จมน้ำ/ครีปเปอร์) | |

### 3.3 ประตู G3: T2 → T3 (อิสระ)
| # | เกณฑ์ | ค่าตั้งต้น |
|---|---|---|
| a | ชั่วโมงเล่นจริงใต้ผู้คุมต่อผู้ฝึกงาน 1 ตัว | ≥ [คิดเอง] 4 ชม. สะสม และผ่านเหตุการณ์กลางคืนอย่างน้อย 1 คืนเกม ("คืนแรก" = คอขวดเก่า) |
| b | **อัตราตาย** ต่อชั่วโมง | ≤ ค่ารุ่นพี่ที่วัดได้ใน s39 (ไม่ใช้ 4.2 เป็นเป้าเพราะเป็นสถิติหลายโลก) และ**ไม่มีการตายซ้ำสาเหตุเดียวกัน ≥2 ครั้ง** |
| c | **AFK** (`idleSeconds>30` ขณะ `nextStep` ยังมีงาน) | ≤ รุ่นพี่ใน s39 · ไม่มีช่วง AFK ยาว > [คิดเอง] 2 นาที |
| d | veto-breach (ผ่าน `allowed()`) | 0 |
| e | ความก้าวหน้า chain (เช่น เหล็กแท่งแรก, ชุดเหล็ก) เทียบรุ่นพี่ | ไม่ช้ากว่ารุ่นพี่เกิน [คิดเอง] 25% ในขั้นที่มีทั้งสองฝั่งทำ (อ้างอิงเวลาดีสุด: เหล็กแท่งแรก 10 นาที (s32), ชุดเหล็กครบตัวแรก 192 นาที (s31), เตียง 24 นาที (s34) — brief §1) |
| f | **kill switch** ทดสอบจริงแล้ว | ผ่าน |

### 3.4 ข้อควรระวังการอ่าน agreement
- รุ่นพี่ผิดได้ → agreement 100% ไม่ใช่ดี ตัวที่ต้องดูคือ `agreement_good` และ `disagree_on_bad` ที่ผ่านการตรวจโดยคน
- ผู้ฝึกงานแต่ละแบบต่างกัน: 27 (กฎล้วน) ตรงโดยโครงสร้าง · 28 (สมองแมลงวันเล็ก) / 30 (FlyWire เต็ม+กฎ) ตัวเลขที่ต่างจากกฎอาจมาจากโมเดล **ไม่ใช่ความรู้ใหม่** → เกณฑ์ลงเล่นจริงใช้กับ**ตัวที่จะลงเล่นจริงจริง** ๆ เท่านั้น (ตัวที่ตัดสินใจผ่าน `decide()`) · brief บอกว่าสมองแมลงวันเป็นรีเฟล็กซ์ไม่ช่วยใน PvP (§1) → อย่าคาดว่า 28/30 จะดีกว่า 27/29 ในงานที่ต้องวางแผน

## 4. เกณฑ์ "พร้อมไปโลกถัดไป" (ย้ายจาก s39 → s40)

ต้องผ่านครบหมวด:

### 4.1 หมวดการเล่น
- รุ่นพี่ (ถ้ายังเล่น) + ผู้ฝึกงานที่ผ่าน G2 อย่างน้อย [คิดเอง] 2 ตัว
- **ผ่านบันได lv0–lv3** ของแล็บ (ไม้ → เตา/อาหารสุก/กิน/บ้าน/เตียง → ตกที่สูง/จมน้ำ/ไฟ/ลาวา/ติดบล็อก → ม็อบ) ใน s39 โดยไม่มีการตายจากสาเหตุที่กฎครอบคลุม
- รู้ที่ต้องปิด: คอขวดเก่า 7 ข้อ (อาหารทีม = 0, ทะเลทรายไม่มีไม้, ตกที่สูง, ยืน AFK, บ้าน/เตียงข้างหลุม, ขุดมือเปล่า, ไม่กินตอนเลือดต่ำ) ต้องมีตัวชี้วัดต่อข้อ และ**ความถี่ใน s39 ต่ำกว่าสถิติเก่า** [คิดเอง ว่า "ต่ำกว่า" วัดต่อชั่วโมง]
- มีข้อมูล s39 ใช้ปรับกฎแล้ว 1 รอบ (IMITATION_DESIGN §8) และ holdout ผ่าน

### 4.2 หมวดซอฟต์แวร์
- `node --test` ผ่านทั้งชุด (ไฟล์เทสที่มีอยู่ เช่น `chain.test.mjs`, `brain.test.mjs`, `adapter.test.mjs`, `home_keep.test.mjs` ฯลฯ)
- fuzz ล่าสุดครอบคลุมชุดกฎปัจจุบันครบ (ตรวจว่าเลขกฎใน `triggers.json` = เลขที่ fuzz รอบล่าสุดใช้ — ณ วันเขียน 102 vs 101 ที่รายงาน) · เหตุการณ์ละ ≥2,000,000 · chain/chainDeep ≥8,000,000 · 0 ช่องโหว่ [ตามกติกา EVENT_INVENTORY]
- ไม่มี `brain:error` ซ้ำ ๆ ในล็อก s39 (ถ้ามีต้องมีคำอธิบายและแก้)
- executor ที่ขาด (§2.2) เขียนแล้วและมีเทส

### 4.3 หมวดการดำเนินงาน
- ตั้งค่าโลก s40 ตามที่ jing ต้องการ (ไม่แตะในแผนนี้)
- สำรองโลก/ล็อก s39 · เวอร์ชันกฎที่ใช้บันทึกไว้ (hash ของ triggers.json + chains.json)
- เกณฑ์ **ไม่ผ่าน** → อยู่ s39 ต่อ หรือย้ายโลกแต่ใช้ T0/T1 เท่านั้น

| `team` ต้องมีโค้ดฝั่งบอตส่งผ่านแชต/สคริปต์กลาง | integration §1 | ทีมไกล = ต้องมีช่องสื่อสารสถานะ (hp/food/ตำแหน่ง/กำลังทำอะไร) ที่ไม่ขึ้นกับระยะการมองเห็น |
| ชังก์ไม่โหลดระยะไกล | กฎ `chunk-unloaded` + `flags.chunkUnloaded` (blockAt null) | ทีมที่เดินไกลอาจเจอชังก์ไม่โหลดบ่อยขึ้น [ไม่แน่ใจ — ขึ้นกับ view-distance/simulation-distance ของเซิร์ฟ ยังไม่ได้ตรวจ] |
| TPS/ping ตกเมื่อโหลดหลายพื้นที่พร้อมกัน | กฎ veto `tps-risky`/`ping-risky` (prio 74/73) | หลายทีมกระจายหลายชังก์ = เซิร์ฟหนักขึ้น [คิดเอง] → veto อาจยิงถี่ ต้องรู้ก่อนว่ายังเดินหน้าได้ไหมเมื่อ veto ค้าง |
| บ้าน/เตียง/ฐานเดียว | chain `home_keep`, กฎ `shelter-breached`, `entrance-blocked` | ทีมไกลควรมีฐานย่อยหรือจุดเกิด (spawn) ของตัวเอง — **กลไกจุดเกิดของเตียงเป็นกลไกเกม ต้องตรวจวิกี่ก่อนวางแผนจริง** [ไม่แน่ใจ ยังไม่ได้ค้น] |
| กลางคืน/ม็อบเริ่มต้นเอง | กฎ `night-exposed` (ต้อง `sheltered`) | ไม่มีเพื่อนช่วย → `teammate-*` ไม่ช่วยเลย; ต้อง self-sufficient เฉพาะกลุ่ม |
| ข้อกำหนดทีมเฉพาะ (เช่น อีเต้อเหล็กให้นักขุด 1 ตัว) | chain `roles` | ต้องกำหนด role ซ้ำทีมละ 1 เมื่อแยก ไม่งั้นทีมที่ไม่มีนักขุดไม่มีอีเต้อเหล็ก |

| ขั้น | รูปแบบ | ระยะ (ตั้งต้น [คิดเอง]) | เงื่อนไขผ่านขั้นก่อน | ถ้าล้ม |

### 5.3 ซอฟต์แวร์ที่ต้องมีก่อน S2
1. **ช่อง relay สถานะทีม** (แชตเฉพาะ/สคริปต์กลาง) ส่ง `{name, hp, food, pos, dim, doing, role, t}` เป็นระยะ [คิดเอง ทุกสิบวินาที — ค่า "สิบวินาที" เป็นเดา] → ป้อน `opts.team()` โดย **คำนวณ dist จากพิกัดที่ส่งมา** (ไม่ใช่จากการมองเห็น) · เพื่อนที่ relay เงียบเกิน [คิดเอง] 60 วินาที = ตั้ง flag `teammateSilent`
2. **flag ใหม่ที่ต้องเพิ่มใน chain.mjs** (เป็นข้อเสนอ ยังไม่ทำ): `teammateSilent` / `teamFar` ให้เกิด reflex "ติดต่อ/กลับหา" ถ้าเงียบนานและมีภัย — เพิ่มได้เมื่อเทส+fuzz ซ้ำเท่านั้น (คำสัญญาของ fuzz ใช้กับชุดกฎที่ fuzz แล้ว)
3. **จุดนัดพบ/ฐาน/เตียง** แยกต่อทีม · ตั้งเป็นพิกัดใน config ไม่ใช่เดา
4. **ตรวจ view-distance/simulation-distance ของ s40** ก่อนกำหนดระยะ S2/S3 (ค่าจริงจากเซิร์ฟ — ฉันไม่ทราบ)

### 5.4 เกณฑ์ผ่านการแยกทีม (ต่อขั้น)
- ไม่มีทีมใดตายทั้งทีมในช่วง ≥ [คิดเอง] 1 วันเกม
- กฎ veto (`tps-risky`, `ping-risky`) ไม่ค้างยิงเกิน [คิดเอง] 10% ของเวลา (ถ้าค้างแปลว่าเซิร์ฟรับไม่ไหว → ลดจำนวนทีม/ระยะ)
- ความก้าวหน้า chain ของทีมแยก ≥ ความก้าวหน้าต่อหัวตอนรวมกลุ่ม ×[คิดเอง] 0.7 (ถ้าต่ำกว่า = แยกแล้วเสียประสิทธิภาพ ไม่คุ้ม)
- เหตุการณ์ "เพื่อนตายไกลและไม่มีใครรู้" = 0 (relay ต้องส่งทัน)
- ช่วง `justDied/respawnGrace` ของแต่ละคนเกิดที่ที่ถูกต้อง (ตามจุดเกิดของทีมนั้น)

## 6. ประตูความปลอดภัย (safety gates) รวม — ใช้ทุกขั้น

### 6.1 Gate ก่อนปล่อยเวอร์ชันกฎใหม่ (ต่อการแก้ triggers/chains)
1. `node --test` ผ่าน
2. fuzz ซ้ำ: ทุกเหตุการณ์ที่แตะ ≥2,000,000 · chain/chainDeep ≥8,000,000 (กติกาเดิมของแล็บ) → **0 ช่องโหว่** · เจอ ≥1 = ปิดแล้วรันใหม่ (seed ใหม่) · **ห้ามรันงานที่แก้ kb/ ระหว่าง fuzz** (บทเรียนรอบ 521)
3. ตรวจ veto: กฎ veto ทุกข้อยังอยู่ ไม่ถูกลด prio/ลบ · มีเทสยืนยัน (อย่างน้อย `bed-wrong-dimension`, `dig-straight-down`, `drop-weapon`, `self-wall-pvp`, `dont-provoke`, `piglin-container`, `ominous-near-village`, `wither-build-site`, `tps-risky`, `ping-risky`, `respawn-grace`, `no-block-in-passage`, `shelter-dirt`, `smelt-no-need`, `ore-claimed`, `sculk-vibration`)
4. บันทึก hash ของไฟล์กฎที่ใช้จริง

### 6.2 Gate ระหว่างเล่น (runtime)
| ตัวคุม | ทำอะไร | หลักฐานที่มี |
|---|---|---|
| ถาม `bot.brain.allowed(action)` ก่อนทำสิ่งเสี่ยงทุกครั้ง | ถ้า `ok:false` → ไม่ทำ | มีใน adapter |
| `respawnGrace` | ห้ามวางบล็อก 60 tick หลังเกิดใหม่ | มีใน adapter |
| **งบการตาย** (death budget) | ผู้ฝึกงานตัวไหนตาย ≥ [คิดเอง] 2 ครั้ง ใน [คิดเอง] 1 ชม. หรือสาเหตุเดียวกันซ้ำ 2 ครั้ง → ลด tier ลง 1 ขั้นทันที และ log สาเหตุ | **ต้องเขียนเพิ่ม** (ไม่มีในโค้ดปัจจุบัน) |
| **AFK watchdog** | `idleSeconds` > [คิดเอง] 120 ขณะ plan มีงาน → เตือน/รีสตาร์ท | `idle` rule (30 วิ, prio 10) มีอยู่แล้ว แต่เป็น reflex เบา — watchdog แยกต้องเพิ่ม |
| **brain:error counter** | ≥ [คิดเอง] 3 ครั้ง/นาที → หยุดท่า (clearControlStates) แล้วแจ้ง | ต้องเขียนเพิ่ม (มี event `brain:error` อยู่) |
| **kill switch** | คำสั่งเดียว (แชตหรือไฟล์ธง) หยุดทุกบอต/ผู้ฝึกงาน → `bot.clearControlStates()` + ปล่อย pathfinder | ต้องเขียนเพิ่ม |
| **tps/ping veto** | `tps-risky`/`ping-risky` ยิง → หยุดท่าเสี่ยง | กฎมีใน triggers (veto) |
| **chunk-unloaded** | หยุดเดิน | executor ค่าเริ่ม |
| จำกัดรัศมี (T2) | ผู้ฝึกงานห่างฐาน/รุ่นพี่เกินระยะ [คิดเอง] → กลับ | ต้องเขียนเพิ่ม |

### 6.3 Gate ตรวจย้อนหลังต่อชั่วโมง (log review)
รายงานชั่วโมงละหน้า: การตายพร้อมสาเหตุ+กฎที่ควรยิง/ไม่ยิง · veto-breach · AFK · `brain:error` · ping/tps · เปรียบเทียบกับรุ่นพี่ → ใช้ตัดสินขั้น/ถอยขั้น

### 6.4 สิ่งที่ fuzz บอกได้ และบอกไม่ได้
| บอกได้ | บอกไม่ได้ |
|---|---|
| `decide()` ไม่มีสถานะที่เข้าเงื่อนไขอันตรายแล้วเลือก "แผน" แทน reflex/veto (ตามกติกาเหตุการณ์ใน EVENT_INVENTORY) | ว่า executor ทำท่าถูกในเกมจริงไหม |
| ลิงก์ไฟล์ kb ที่อ้างอิงมีอยู่จริง (ตามกติกา "ลิงก์ kb ต้องมีจริง") | ว่า state ที่ `toState()` สร้างจากบอตจริงถูกต้อง (บิตติดไฟ, ระยะตก) |
| ลำดับ chain ไม่ขัดกัน (chain/chainDeep) | ว่าเซิร์ฟ/แล็ก/ชังก์/ping จริงทำให้ตัดสินช้าไหม |
| – | ว่ากฎใหม่จากข้อมูลศุกร์ปลอดภัย (ต้อง fuzz ใหม่) |
